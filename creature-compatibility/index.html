    Creature compatibility: design

    Status: DESIGN ONLY. No firmware code is changed by this document. Base: origin/feat/land-edition at bbe1a7a (main does not yet carry the Land registry, so this doc needs a rebase once Land is merged). Branch: docs/creature-compatibility.

    Everything marked R below was read in the code; I marks my inference. Nothing here has been built or run; flash/RAM numbers other than the quoted Heltec V3 builds are estimates.

    0. What the code does today (read, not inferred)

    • Registry (examples/companion_radio/LoRaFishSpecies.h): one shared ID space. Water 0..14 (15), Air 256..273 (18), Land 512..550 (39), 72 species in total. IDs are permanent. known() already accepts all three ranges; editionKnown() limits a build to its own range. Water art is compiled into every species build, Air art only in Air builds, Land art only in Land builds (sprite dispatch at UITask.cpp ~2111-2140: a Land build draws Land + Water, an Air build draws Air + Water, a Water build draws Water only; anything else is drawn as the fish).
    • Movement is already a per-species fact, but only for drawing: movement() returns Swim / FlyMotion / Flutter / Walk / Crawl. It is presentation, nothing in the protocol uses it.
    • Visit handshake (MyMesh.cpp ~584-770), all text messages starting LFG1|: REQ|tx|fid|stage|name (host parses %lu|%lu|%u|%23[^\n]), then ACK|tx|fid with a suffix chosen by the host's build: none = DX, |S1 = Water, |S1|A1 = Air, |S1|L1 = Land. The visitor accepts only those exact strings (acknowledged()). Only after an accepted suffix does it add |S1|<speciesId> to COMMIT; otherwise it sends the old nine-field COMMIT and the pet is shown as the fish ("FISH FALLBACK"). Air/Land IDs need the matching A1/L1 suffix; Water IDs pass with any S1 form. Other replies: BUSY, RECALL, RETURN|..|CANCEL1. An unknown LFG1|.. opcode is silently dropped (the block ends in return;).
    • So there is no version field and no visitor-side capability. The host announces its edition in the ACK; the host never learns the visitor's edition before COMMIT.
    • Who is eligible to visit is decided by a name marker only: loRaFishDXEligible() (UITask.cpp ~2899) calls LoRaFishText::hasFish(), which is hasDiscoveryMarker(): the four legacy fish emoji everywhere, plus Water markers (Water/Air/Land builds), Air markers (Air build only), Land markers (Land build only). The code itself says markers are "discovery hints only, never proof of habitat".
    • Today the only compatibility rule is "does the host's build contain my art; if not, show the fish". There is no concept of a land animal being unable to visit water.

I did not apply those upgrades because the code does not say so; the owner can switch any of them on by changing one table row.

    2. Compatibility model

    Firmware-side, data-driven, no emoji. One byte per species in the registry:

    Zone bits:   WATER=1  LAND=2  AIR=4     // used for sets, homes and reach alike
Ability bits SWIM=1   WALK=2  FLY=4  MYTHIC=8   (bit 4 reserved for CLIMB)

struct Traits { uint8_t home; uint8_t abilities; };   // 2 bytes x 72 = 144 bytes of flash
set(id)   = Water / Air / Land by ID range           // already free from the ID
reach(id) = home | (SWIM?WATER) | (WALK?LAND) | (FLY? AIR|LAND)
canVisit(visitor, host) = set(visitor)==set(host)  ||  (reach(visitor) & home(host)) != 0

    Unknown or future IDs use the fish row (Water, Swim), which is what renderId() already does. Invariant for a host test: home is always a subset of reach, and the traits agree with movement() (Walk/Crawl rows have no FLY, FlyMotion/Flutter rows have FLY).

    Rules

    # Rule Effect
    R0 Same set always visits same set Water-Water, Air-Air, Land-Land keep working exactly as today.
    R1 Swim reaches WATER hosts A water animal visits water and amphibious hosts.
    R2 Walk (and crawl) reaches LAND hosts A land animal visits land, amphibious and land+air hosts.
    R3 Fly reaches AIR hosts and LAND hosts Fliers can visit sky tanks and perch on land.
    R4 Fly alone does NOT reach WATER hosts A bat or eagle cannot visit a shark tank. Fliers get water access only with Swim.
    R5 Amphibious (Swim+Walk) reaches WATER and LAND Frog, Crocodile, Turtle; and their hosts accept both swimmers and walkers.
    R6 A walker cannot reach an AIR-only host "Not every creature that walks can fly." Dog cannot visit Eagle; Eagle can visit Dog.
    R7 No Water creature has FLY "Very few water creatures can fly": in the current list none, so Water-to-Air is closed.

    Outcome by visitor type (cross-set; R0 aside). ✓ = allowed, ✗ = blocked.

    Visitor can host WATER host LAND host AIR host WATER+LAND host LAND+AIR
    Swim only (15 Water) ✓ ✗ ✗ ✓ ✗
    Walk only (40 grounded) ✗ ✓ ✗ ✓ ✓
    Fly only (12 sky) ✗ ✓ ✓ ✓ ✓
    Swim + Walk (Frog, Crocodile, Turtle) ✓ ✓ ✗ ✓ ✓
    Walk + Fly (Dragon, Griffin) ✗ ✓ ✓ ✓ ✓

    (Swim+Fly would reach everything; no species has it unless Duck/Swan are upgraded.)

    Species-pair counts that result (visitor species set, then host set; allowed / all pairs): Water to Water 225/225; Water to Air 0/270; Water to Land 45/585 (only the 3 amphibious hosts); Air to Air 324/324; Air to Water 0/270; Air to Land 695/702 (blocked only into the Phoenix tank by the 7 grounded Air-set birds and bugs); Land to Land 1521/1521; Land to Water 45/585 (only the 3 amphibious visitors); Land to Air 306/702.

    Arguments on the rules I am unsure about

    • R0 (same set always allowed). For: the grounded Air-set animals (Penguin, Turkey, Worm, Bug...) would otherwise be unable to visit their own Air friends, which is a regression for every Air player. It also keeps the old "I installed the Air edition, I can see Air friends" promise. Against: it makes the habitat model only matter across editions, and it lets a Worm visit an Eagle's sky tank. I recommend keeping it; the alternative is a per-species fix (give the Air birds home AIR+LAND), which is more data to maintain.
    • R3 (Fly reaches LAND). Birds, bats and insects land; the sprite already draws fliers hovering above a ground line in a land scene. Low risk. Without it, Land owners could never receive any Air animal.
    • R4 (Fly does not reach WATER). The owner's draft rule says fliers may visit water hosts "where they can perch or hover". The Water tank is an underwater scene; a honeybee in a shark tank is wrong and there is no surface or perch drawn. I recommend: only Swim reaches water, so waterfowl are the way in (Duck, Swan after upgrade). Variant B (any flier hovers over water) is one line, section 7 item 2.
    • R5 hosts accept both. An amphibious host is a shore scene: both a swimmer and a walker can plausibly meet it. The cost is that Shark can visit Frog and Dog can visit Frog, though Shark and Dog still cannot visit each other. That is the intended asymmetry.
    • Climb. I left it out: it adds a bit but no rule (a climbing animal still reaches LAND). Bit 4 is reserved so Koala/Sloth can get it later if the owner wants art/animation only.
    • Symmetry. Visits are directional (the visitor must reach the host's home). A pure "share a habitat" rule would let Dog visit Eagle, contradicting the owner's examples.

    3. How a remote peer tells us its capabilities (the wire)

    Two things must not be confused: can the host draw my art (art mask, exists today as S1/A1/L1) and may I visit this host (new, from the species traits). A host's home is needed, and a Dog cannot tell its host's home from today's ACK except by edition.

    Phase 0: no wire change at all (smallest possible)

    The visitor already receives the host's edition in the ACK. Map it to the host's set and home:

    ACK suffix Host set Host home Art host can draw
    none (DX) Water (fish) WATER fish only
    S1 Water WATER Water
    S1\|A1 Air AIR Water + Air
    S1\|L1 Land LAND Water + Land

    Then in the ACK handler, before prepare(), call canVisit(localSpecies, hostSet, hostHome). If false, do what the BUSY branch already does (clear pending/committing/away, visit.stop()) and also send LFG1|RECALL|tx|fid: the host's existing RECALL branch with a reserved guest releases the reservation at once. Show a new message ("CAN'T REACH THAT HOME"). Fish fallback for missing art stays as it is. Lossiness: an Air-edition host that happens to own a Worm (really LAND) is treated as AIR, so walkers are refused. That is conservative. Older builds are untouched: nothing new is sent.

    Phase 1: C1 capability token (needed for DX-Pro, optional before)

    Hosts in DX-Pro can hold any species, so the edition no longer says what the host is. Add two small tokens. Each digit is one hex character using the zone bits above.

    • Visitor to host: add a second line to REQ: LFG1|REQ|tx|fid|stage|name\nC1|<set><reach> e.g. a Frog visitor (set Land=2, reach WATER+LAND=3): C1|23.
    • Host to visitor, only when the REQ carried C1: LFG1|ACK|tx|fid|S1|C1|<set><home><art> e.g. a Dog host (set Land=2, home LAND=2) in a build that carries Water and Land art (1+2=3): S1|C1|223.
    • Host-side refusal: reply LFG1|BUSY|tx|fid|NC1 without reserving the slot. Legacy visitors parse only the prefix and treat it as BUSY; new visitors read NC1 as "not compatible".

    Does it break older builds? No, by construction: - Legacy host receiving a new REQ: its parser stops the name at the first newline (%23[^\n]), so the C1 line is ignored; it replies with its old ACK; the new visitor falls back to Phase 0 logic. (To verify on hardware/CI: that a newline survives the MeshCore text path unchanged. If not, send the line as a separate LFG1|CAP|.. message; legacy drops unknown LFG1 opcodes silently, at the cost of one extra packet.) - Legacy visitor (including every DX-only build) receiving from a new host: no C1 in the REQ, so the host answers with the legacy ACK form for its current pet's set (none/S1/ S1|A1/S1|L1), exactly as today. A new suffix must never be sent to a legacy visitor, because acknowledged() is a strict whole-string match and would downgrade the visit to the fish. - Unannounced visitors (no C1): the host cannot evaluate them. Recommended policy: allow, and they are shown as today (species by S1, otherwise the fish). Alternative is deny; section 7 item 3. The host should still re-check the species in COMMIT (it can look the ID up in its own registry) and answer RETURN|..|CANCEL1 if the owner chose "deny". - If old Water/Air/Land test builds need not stay at full fidelity (the docs say no release has been made), the REQ line can be dropped and the C1 suffix put straight on the ACK; old species builds would then show new-host visitors as the fish. I recommend the REQ line anyway: it costs ~5 bytes.

    Budget: REQ ~ 33 + 23 name + 1 + 5 ~ 62 bytes (buffers are 112); ACK ~ 40 bytes (buffer 80). No change to COMMIT, ARRIVED, RETURN, RECALL or the saved records.

    4. Replacing the emoji markers

    Honest limit: a contact's advert carries only a name, so the visitor does not know the host's species before the handshake. A registry lookup therefore cannot replace the marker for discovery; it replaces it for compatibility.

    1. Discovery stays name-based but is generated from the registry: add one glyph codepoint column to the species table (72 entries, ~300 bytes). isWaterMarker, isAirMarker, isLandMarker (three hand-kept switches) become one lookup speciesForGlyph(code). A name is a LoRagotchi tank if it contains any registry glyph.
    2. Compatibility is decided by the handshake and the traits (sections 2 and 3), never by the name. The glyph is also a hint: speciesForGlyph gives a guessed host species, so the picker can mark contacts that probably cannot be visited. The hint never blocks sending; the ACK or the host's BUSY|NC1 is final.
    3. Existing contact names keep working with no rename: 🐟 🐠 🐡 🦈 (fish), the Water/Air/Land emoji and 💦 all stay valid markers. Names with several markers use the first glyph for the hint. Names with no marker are not listed, as today. Phoenix still has no single-codepoint glyph and stays unmarked (comment in LoRaFishText.h).
    4. Which builds see which markers. Today an Air build ignores Land markers, which would hide Land friends it can now visit. New rule: every species build recognises the union of all glyphs (compatibility is the handshake's job). DX-only builds keep exactly the four fish glyphs and the ><> display fallback; there is no reason to change them (they have no species to compare).
    5. Display fallback for the small fonts: ><> for fish, [W] / [A] / [L] by the glyph's set (replaces the three-way ternary in display()).
    6. The "Add a Water/Air/Land emoji to your name" notice (UITask.cpp ~3712) becomes "Add an animal emoji" in DX-Pro; per-edition text is unchanged elsewhere.
    7. protocolName() keeps stripping every emoji from the wire name, unchanged.

    5. DX-Pro: one firmware, every set

    What has to change (IDs do not)

    • IDs: no change. The ID space is already disjoint and permanent, and known() already accepts all three ranges. Saves (SPC1, 18 bytes) store the ID, so a pet created in any edition loads in DX-Pro.
    • Build flag. Replace "select one habitat edition" (#error in LoRaGotchiVersion.h) with a set mask using the same zone bits (WATER=1, LAND=2, AIR=4; or one PRO flag = all three). editionKnown(id) becomes ownsSet(set(id)). Existing single-set builds keep working as masks of one bit.
    • Art and dispatch. Include all three sprite headers; the compile-time #if chain at UITask ~2111-2140 becomes a per-ID branch (Land ID -> Land sprite, Air ID -> Air sprite, else Water).
    • Menu. selectableCount, selectionId, selectionIndex, freshSpecies, and mystery(seed) are compile-time constants for one range. For 72 species use two steps: pick the set (Water / Air / Land), then the species in that set (largest list stays 39, the Land length today). Only the species ID is persisted, the set is derived from it, so no save-format change. Mystery egg: draw inside the chosen set with the same formula as today (set count and base), so an existing seed gives the same animal as in the single-set build. The value picker count is a uint8_t and would still hold 73 entries, so a flat list is technically possible but not recommended.
    • UI strings ("CHOOSE LAND PET" etc.) become "CHOOSE PET" with the set name.
    • Breeding (editionKnown(guest.species) at UITask ~993) becomes ownsSet(): any set the device owns. Cross-set eggs are reachable only through allowed visits.
    • Wire. A DX-Pro host answers legacy visitors with the legacy ACK of its current pet's set, and C1 visitors with section 3. Receiving already accepts every known ID.
    • Targets/CI. Add pro_* aliases for the 16 screen boards, extend test/boards/check_edition_targets.py and add a native_pro test environment.

    Flash and RAM

    Measured on Heltec V3 (quoted from the earlier builds, logs in /tmp/land-{water,air,land}_heltec_v3_ble.log):

    Build Flash used % of 3,342,336 Static RAM
    Water 1,346,221 40.3% 174,780
    Air 1,353,845 40.5% 174,780
    Land 1,362,017 40.8% 174,780

    Air costs +7,624 over Water (its art is 6,912 bytes); Land costs +15,796 (art 14,976 bytes). So the extra sets cost almost exactly their art, and RAM is identical (the masks are constant data in flash).

    DX-Pro estimate (Heltec V3): 1,346,221 + 7,624 + 15,796 = 1,369,641, plus runtime set-dispatch, the two-step menu and the 144-byte trait table, say +5 to 10 KB: about 1.375 to 1.38 MB, roughly 41-42% of the app partition (about 1.96 MB spare). RAM about 174,780 plus a few hundred bytes (still ~53%). The static numbers say nothing about heap or stack during the sprite draws; those are unmeasured.

    Build DX, Water or Air from main

    One repository, one shared source: main. Choose an edition and board with its case-sensitive PlatformIO environment; do not hunt for an old feature/fix branch. Existing LoRaFish/LoRaGotchi environment names select DX. Only explicit water_* or air_* aliases select those habitat editions. Mono/colour handling is shared, not a separate firmware branch.

    Start once

    Install PlatformIO Core, then:

    git clone --branch main https://github.com/DrToxic/LoRagotchi-DX.git
cd LoRagotchi-DX
pio run -e water_heltec_v3_ble -j 1

    Replace the environment with one from the table. For nRF52 append -t create_uf2; ESP32 builds produce an application BIN. Build only the selected environment, never an unqualified pio run over inherited MeshCore targets.

    The aliases inherit their DX board's pins, RF, memory and dependencies; see Water definitions and Air definitions. Other DX-only boards remain in the README and experimental screen matrix. RAK modules require the fitted display, carrier and controls described in RAK4630 prerequisites. A target name or successful compile is not physical hardware acceptance.

    Find the result; flashing is separate

    • ESP32: .pio/build/<environment>/firmware.bin (application only, not an installer).
    • nRF52: .pio/build/<environment>/firmware.uf2, after -t create_uf2.

    For the USB upload command, UF2 copy procedure and pre-install backup checklist, see README: build and install. Use the same environment for building and installing; choose the exact board variant rather than a similarly named target.

    Do not assume an application BIN belongs at address zero. Station G2/G3 and T-Beam 1W now use a single factory app and no OTA; an app-only update cannot migrate an old partition table. Read the migration/data-loss warning and back up first. Matching data geometry is not a data-retention guarantee.

    GitHub-hosted builds and product scope

    For existing workflow names, bounded matrices, exact-commit artifacts and their 14-day retention, see GitHub firmware builds. When manually running a workflow, select main; matrices differ and no single workflow builds every board/edition. No workflow success implies a published release, hardware acceptance or permission to flash.

    Current source provides DX, Water (14 species) and Air (18 animals), not a new firmware release. The shared source already selects these by build target. Future Water/Air product branding or distribution channels need a separate decision, not duplicate source-maintenance branches. Land and combined-habitat products remain future work. See Water and Air for saves, adoption and negotiated visiting fallbacks.
